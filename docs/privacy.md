# 隐私与媒体处理

## 信任边界

前端只负责预览和提交隐私矩形。所有公开发布的媒体必须由 Node.js API/Worker 使用服务端 Sharp 管线生成。客户端上传的“已模糊图片”仍会重新处理，不能直接进入公开桶。

## 处理步骤

1. API 校验用户、文件类型、大小和配额。
2. API 返回短期签名 URL，浏览器将原图上传到私有 `map-quarantine` 桶。
3. `/media/uploads/:id/complete` 校验对象确实存在且大小一致。
4. Worker 从隔离桶读取原图。
5. 如果启用 ClamAV，先执行 `INSTREAM` 恶意文件扫描。
6. Sharp 按 EXIF 方向旋转图片，并在重新编码时移除 EXIF/GPS 等元数据。
7. Worker 合并用户矩形和可选检测器返回的敏感区域。
8. 服务端对区域进行安全边距扩展和模糊。
9. Worker 重新编码 WebP 并生成缩略图、SHA-256 和感知哈希。
10. 没有自动检测器时，处理结果停留在私有桶并标记 `manual_review`。
11. 审核员通过 10 分钟签名 URL查看私有处理结果并确认隐私。
12. 只有确认后，处理图和缩略图才复制到公开桶并标记 `ready`。
13. 原图默认在 24 小时后由维护任务删除；失败媒体最多保留 7 天。

## 对象台账与对账

- 每次对象写入、重写（重试）、删除都会写入 `media_object_events` 台账，包含桶、对象键、操作方和字节大小；媒体所有者与审核员可通过 `GET /media/:id/object-events` 追溯完整生命周期。
- Worker 在写入派生对象后立即把对象键登记到 `media_assets`，再执行后续步骤；处理中断不会留下无归属的私有对象。
- 维护任务每分钟对隔离桶和公开桶执行对账：能从键解析出媒体 ID 且行内引用缺失的对象会被重新认领（`adopt`）；无法归属或属于已删除媒体的对象在宽限期（`MEDIA_ORPHAN_GRACE_MINUTES`，默认 60 分钟）后清除（`purge`）。台账建立之前的存量孤儿同样按此规则处理。
- 公开桶对象只在媒体处于 `ready` 时才会被认领；其余公开孤儿一律清除，保证公开桶只保存隐私确认过的派生图。

## 数据要求

- 原始文件对象键不可预测，隔离桶不允许匿名读取。
- 公开桶只允许已经过隐私确认的派生图。
- 日志中不得记录原图 URL、访问令牌、密码或完整个人信息。
- 默认不采集用户定位轨迹；浏览器定位必须由用户主动触发。
- 私人住宅内部、受限区域和实时人员位置不属于 V1 允许内容。
- 删除媒体时同时清理隔离原图、服务端处理图和公开派生图。
